## 4. Cloud(gpt-5.6-luna) 비교 결과

**품질** (동일 5개 질문 Q1/Q3/Q5/Q7/Q9 기준, Cloud n=5 vs Local n=10)

| | qwen2.5:7b | exaone3.5:7.8b | gpt-5.6-luna |
|---|---|---|---|
| 정확성 | 4.6 | 4.3 | **5.0** |
| 핵심정보누락 | 3.8 | 4.0 | **4.6** |
| 지시형식준수 | 4.0 | 4.0 | **4.8** |
| 한국어표현 | 5.0 | 4.8 | 5.0 |
| 정보부족시대응 | 5.0 | 5.0 | 5.0 |

Luna가 5개 기준 중 4개에서 로컬 두 모델을 앞섰다. 특히 Q5(추미애 청원 기사 2건)에서 로컬 모델들은 대부분 "논조 차이 없음"으로 단순화한 반면, Luna는 두 기사의 실제 강조점 차이(리더십 위기 프레이밍 vs 절차·양측입장 병렬제시)를 정확히 짚어냈다.

**속도**: Luna 평균 4.83초(n=5, 네트워크 포함) — 네트워크 왕복이 있음에도 Qwen(4.21초)과 비슷했고 EXAONE(5.36초)보다 빨랐다.

**비용**: 5회 호출 합계 추정 $0.003593 — 사실상 무시할 수준.

**해석 시 유의할 점**: Cloud는 질문당 1회만 실행해 재현성을 측정하지 못했다. 품질 우위가 확인됐다고 해서 반복 시에도 안정적인지는 이번 실험만으로 단정할 수 없다.

## 5. 최종 선정

> Luna(Cloud)가 품질 5개 기준 중 4개에서 로컬 두 후보를 앞섰지만, 우리는 qwen2.5:7b를 최종 선정했습니다.
> 이 프로젝트는 애초에 "기사 원문이 외부로 나가지 않는 로컬 뉴스 요약 시스템"을 목표로 시작됐고, 실제 서비스 관점에서도 인터넷 연결이나 외부 API 키 없이 독립적으로 동작해야 한다는 요구가 있었습니다.
> Cloud 비용은 이번 규모($0.0036/5회)에서는 무시할 만한 수준이라 비용 자체가 결정 요인은 아니었습니다. 결정적인 이유는 데이터가 로컬 PC를 벗어나지 않는다는 점과, 인터넷 연결 없이도 동작하는 오프라인 독립성이었습니다.

**선정 후보**: qwen2.5:7b (Alibaba, Apache 2.0)

**선정 근거**:
1. **재현성**: 동일 입력(temperature=0)에 대해 Qwen은 10문항 전부 rep1·rep2 결론이 일치(100%)했지만, EXAONE은 3개 문항(Q3, Q5, Q9)에서 결론이 뒤바뀜(70% 일치). 판단의 근거로 재사용할 요약 시스템에서는 이 차이가 실무적으로 중요함.
2. **라이선스**: Apache 2.0이라 향후 상업적 활용까지 열려 있음(EXAONE은 연구목적 허용에 한정).
3. **품질 차이는 근소함**: 정확성 4.6 vs 4.3, 핵심정보 3.8 vs 4.0, 지시형식 4.0 vs 4.0 — 우열이 기준별로 엇갈리고 격차가 크지 않아, 위 두 요인이 우선순위를 결정지음.

**Cloud(Luna) 활용 시나리오**: 품질이 최우선이고, 기사 원문의 외부 전송이 허용되며, API 비용을 감수할 수 있는 상황(예: 대량 처리, 높은 정확도가 요구되는 용도)이라면 Luna를 대안으로 고려할 수 있음. 이번 실험에서 Luna의 품질 우위와 낮은 비용은 이를 뒷받침함.

## 6. 한계점

- 평가셋이 10개 질문(그중 Cloud 비교는 5개)으로 소규모라 통계적으로 유의미한 차이라 보기 어려움
- 제한된 장비(8GB VRAM 1대)에서만 측정, 다른 하드웨어 환경에서는 결과가 달라질 수 있음
- Q7·Q8은 애초 설계한 "정보부족 트랩" 조건에 맞는 실제 기사를 찾지 못해 합성(가상) 기사로 대체함 — 실제 뉴스 환경에서의 정보부족 대응력은 별도 검증 필요
- Cloud는 1회, 로컬은 2회 실행해 반복 수가 달라 재현성 비교의 엄밀도가 다름

## 7. 개선이 필요한 실패 사례

- **EXAONE Q9 rep2**: 본문에서 두 기사의 차이를 구체적으로 서술해놓고, 결론에서 "논조 차이 없음"이라고 스스로의 분석과 모순되는 진술을 함. 같은 질문의 rep1에서는 "논조 차이 있음"으로 답해 재현성도 함께 깨짐.
- **Qwen/EXAONE 공통, 단일 기사 질문(Q1/Q2)**: 시스템 프롬프트가 "기사 1개뿐이면 논조 차이 항목 생략"을 지시했음에도, 두 모델 다 "논조 차이 없음"이라는 문구를 넣어 마치 두 기사를 비교한 것처럼 서술함. Luna는 이 지시를 정확히 지켜 해당 항목 자체를 생략함 — 로컬 모델의 지시 준수력이 상대적으로 약한 지점.
- **Qwen/EXAONE 공통, Q5(경계 사례)**: 실제로는 기사2가 기사1보다 더 많은 내용(김동연 전 지사 반응 등)을 포함하고 있음에도, 대부분 "논조 차이 없음"으로 단순화해 미묘한 차이를 놓침.

## 8. Local–Cloud 운영 방식 권고

- **개발·검증 단계**: Cloud(Luna)로 빠르게 프로토타입을 검증하고 품질 기준선을 잡는 것을 권장. 비용이 매우 낮아 초기 테스트에 부담이 없음.
- **실서비스 전환 시**: 기사 원문에 민감 정보가 없고 처리량이 적다면 로컬(Qwen2.5-7B)로 유지해 비용·데이터 통제 이점을 살리는 것을 권장.
- **처리량이 커지거나 품질이 최우선 순위가 되면**: 그 시점에 Cloud API로 전환하거나, 로컬-Cloud 하이브리드(예: 평상시 로컬, 품질이 중요한 사례만 Cloud로 라우팅)를 고려.
- **공통 권고**: 이번 실험에서 드러난 "단일 기사에서 불필요한 논조비교 문구 삽입" 문제는 시스템 프롬프트를 더 명확히 하거나(예: 조건문을 더 강하게 명시), 후처리 단계에서 걸러내는 방식으로 개선 가능.
