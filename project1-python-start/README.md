# 뉴스 요약 QA 시스템 — 로컬 LLM 모델 선정 프로젝트

사용자가 질문과 관련 기사 원문을 직접 입력하면 로컬 LLM이 핵심 사실을 요약하고
기사 간 논조 차이를 비교해서 답변하는 QA 시스템을 만들기 위해, 후보 모델을 선정하는 과정을 정리한 문서입니다.

## 1. 사용 사례

> 사용자가 궁금한 주제/질문과 관련 기사(1~2개)를 직접 입력하면, 로컬 LLM이
> 1) 핵심 사실 요약, 2) 기사 간 논조/관점 차이를 답변하는 QA 시스템

- Task를 Chat이 아닌 **QA**로 설계 (근거 문서 기반 답변이 정확성 요구사항에 더 부합)
- 기사는 항상 **사용자가 직접 붙여넣음** (검색 자동화는 비용·네이버 API 약관 문제로 제외)

## 2. 요구사항 (STEP 2)

| 항목 | 확정 내용 |
|---|---|
| Language | 한국어 |
| Model Size | 8GB VRAM에서 오프로드 없이 구동 (다운로드 용량 5~6GB 이하) |
| License | 부트캠프 비상업 프로젝트 → 상업/비상업 라이선스 모두 허용 가능 |
| Context Length | 입력 기사 1~2개(약 2~4K 토큰), 출력 길이 제한 없음 |
| GPU | 실측 VRAM 8151MiB, 드라이버 592.01 |
| RAM | 32.0GB |
| Task | QA (질문 + 기사 직접 입력) |

#### 1. Quantization 비교

동일한 Qwen3-8B 모델의 `Q4_K_M`과 `Q6_K` 양자화 버전을 비교하였다.

* 모델 크기 비교
* CPU/GPU 실행 비율 확인
* 생성 속도 측정
* GPU 메모리 사용량 확인
* 동일한 5개 질문을 이용한 답변 품질 비교

실험 결과, 이번 환경에서는 Q4_K_M이 Q6_K보다 작은 모델 크기와 높은 생성 속도를 보였다. 반면 5개 질문에 대한 품질 평가에서는 두 모델 모두 47/50점으로 동일했다.

> 두 모델 모두 8GB VRAM 환경에서 CPU/GPU 분할 실행되었기 때문에 생성 속도의 차이를 양자화 수준의 차이만으로 단정하지 않았다.

#### 2. Embedding 실험

문장을 임베딩 벡터로 변환한 후 Cosine Similarity를 이용하여 문장 간 의미적 유사도를 비교하였다.

* `paraphrase-multilingual-MiniLM-L12-v2` 모델 사용
* 3개의 한국어 문장을 384차원 벡터로 변환
* 문장 간 Cosine Similarity 계산
* 유사한 문장과 서로 다른 주제의 문장 비교

`고양이가 소파 위에 있다`와 `소파 위에 고양이가 앉아 있다`는 **0.9466**의 높은 유사도를 보였고, `오늘 주식시장이 상승했다`와의 비교에서는 **0.0628**로 낮은 유사도를 보였다.

이를 통해 임베딩을 이용하면 문장 간 의미적 유사도를 수치로 비교할 수 있음을 확인하였다.

> Cosine Similarity가 높다는 것이 문장의 사실 여부를 의미하는 것은 아니며, 의미적 유사도를 확인하는 지표로 사용하였다.

📊 **[Embedding 비교 결과 보기](./embedding_비교표.md)**

#### 3. 오늘 실험에서 확인한 점

* 양자화 수준에 따라 모델 크기와 생성 속도에 차이가 발생할 수 있음을 확인했다.
* 8GB VRAM 환경에서는 Q4_K_M과 Q6_K 모두 CPU/GPU 분할 실행이 이루어졌다.
* 따라서 모델 간 속도 차이를 양자화 수준만의 영향으로 판단하기 어렵다는 점을 확인했다.
* 5개 질문에 대한 품질 평가에서는 Q4_K_M과 Q6_K의 뚜렷한 차이가 나타나지 않았다.
* 임베딩을 이용하면 문장을 숫자 벡터로 변환하고 문장 간 의미적 유사도를 비교할 수 있음을 확인했다.
* 임베딩의 Cosine Similarity는 의미적 유사도를 나타내는 지표이며, 정보의 사실 여부를 판단하는 지표는 아니라는 점을 확인했다.
