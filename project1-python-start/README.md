# 뉴스 요약 QA 시스템 — 로컬 LLM 모델 선정 프로젝트

**뉴스 요약 QA 시스템의 로컬 LLM 모델 선정 과정**을 정리한 문서입니다.

사용자가 질문과 관련된 기사 원문을 직접 입력하면, LLM이 기사에 근거하여 핵심 내용을 요약하고 기사 간 논조 및 관점 차이를 비교해 답변하는 QA 시스템을 목표로 합니다.

본 프로젝트에서는 **8GB VRAM 환경에서 구동 가능한 한국어 지원 LLM 2종을 선정하고, 동일한 평가 기준으로 비교 실험을 진행한 뒤 최종 로컬 모델을 선정**했습니다. 또한 선정 과정의 참고를 위해 Cloud API 모델과도 소규모 비교를 진행했습니다.

---

## 1. 사용 사례

### 시스템 목표

사용자가 궁금한 주제와 관련된 질문 및 기사 원문 1~2개를 직접 입력하면, 로컬 LLM이 다음과 같은 답변을 생성합니다.

1. 기사 핵심 사실 요약
2. 기사 간 논조 및 관점 차이 비교
3. 기사에 없는 정보에 대한 적절한 대응

### 설계 방향

* Task를 일반적인 **Chat**이 아닌 **QA(Question Answering)** 형태로 설계
* 답변은 사용자가 제공한 기사 원문을 근거로 생성
* 기사는 사용자가 직접 입력
* 뉴스 검색 자동화는 비용 및 네이버 API 약관 등을 고려하여 프로젝트 범위에서 제외
* 외부 API로 기사 원문을 전송하지 않고 **로컬 환경에서 독립적으로 실행 가능한 시스템**을 목표로 함

## 4. 평가 설계 — STEP 5·6

### 평가 데이터

총 **10개의 고정 질문**을 사용했습니다.

| 사례 유형           |   문항 수 |
| --------------- | -----: |
| 정상 사례           |      6 |
| 경계 사례           |      2 |
| 정보 부족 / 범위 밖 사례 |      2 |
| **합계**          | **10** |

평가 질문은 단순 요약뿐 아니라, 기사에 없는 정보에 대한 대응과 기사 간 비교가 필요한 상황까지 포함하도록 구성했습니다.

### 채점 기준

각 응답을 다음 5개 기준으로 평가했습니다.

1. **정확성**
2. **핵심정보 누락**
3. **지시·형식 준수**
4. **한국어 표현**
5. **정보 부족 시 대응**

### 실험 조건

* 로컬 모델 2종
* 질문 10개
* 질문당 2회 반복
* 모델당 총 **20회 본실험**
* 워밍업 1회는 집계에서 제외
* `temperature=0`
* `num_ctx=4096`

따라서 로컬 모델별 결과는 **20회 실행 기준**으로 집계했습니다.

## 5. 로컬 실험 결과

| 지표       | Qwen2.5-7B | EXAONE 3.5-7.8B |
| -------- | ---------: | --------------: |
| 호출 성공률   |      20/20 |           20/20 |
| 정확성      |       4.20 |            4.25 |
| 핵심정보 누락  |       3.90 |            4.10 |
| 지시·형식 준수 |       4.20 |            4.30 |
| 한국어 표현   |       5.00 |            4.90 |
| 평균 응답시간  |      4.12초 |           5.02초 |
| VRAM 사용량 |  4,528 MiB |       4,945 MiB |
| **재현성**  |   **100%** |         **70%** |

> 점수는 5점 만점 기준입니다.

#### ② EXAONE에서 반복 실행 결과가 달라지는 현상 확인

`temperature=0`으로 설정했음에도 EXAONE에서 일부 질문의 반복 실행 결과가 달라졌습니다.

특히 **Q3, Q5, Q9**에서 rep1과 rep2의 결론이 달라지는 사례가 확인됐습니다.

| 모델              | 동일 입력 반복 결과 일치율 |
| --------------- | --------------: |
| Qwen2.5-7B      |        **100%** |
| EXAONE 3.5-7.8B |         **70%** |

동일한 질문에 대한 결과의 일관성이 필요한 시스템 특성을 고려할 때, 반복 실행 결과도 모델 선정의 참고 지표로 활용했습니다.

---

#### ③ 기사 1개 입력 시 불필요한 논조 비교 발생

두 모델 모두 기사 1개만 제공된 질문에서 **"기사 간 논조 차이가 없다"**는 내용을 불필요하게 서술하는 사례가 확인됐습니다.

시스템 프롬프트에서 기사 간 비교가 불가능한 경우 해당 내용을 생략하도록 지시했지만, 일부 응답에서 이 지시가 제대로 지켜지지 않았습니다.

이는 향후 **프롬프트 개선 및 출력 형식 제어**가 필요한 부분으로 확인했습니다.

## 6. Cloud 비교

로컬 모델 선정 결과를 참고하기 위해 Cloud API 모델과도 소규모 비교를 진행했습니다.

미리 선정한 5개 질문인 **Q1, Q3, Q5, Q7, Q9**를 GPT-5.6 Luna에 각각 1회 실행했습니다.

> ⚠️ 로컬 모델은 질문당 2회, Cloud 모델은 질문당 1회 실행했기 때문에 반복 실행에 따른 재현성을 직접적으로 동일 조건에서 비교한 실험은 아닙니다.

| 지표       | Qwen2.5-7B | EXAONE 3.5-7.8B | GPT-5.6 Luna |
| -------- | ---------: | --------------: | -----------: |
| 정확성      |        4.6 |             4.3 |      **5.0** |
| 핵심정보 누락  |        3.8 |             4.0 |      **4.6** |
| 지시·형식 준수 |        4.0 |             4.0 |      **4.8** |
| 한국어 표현   |        5.0 |             4.8 |      **5.0** |
| 평균 응답시간  |      4.21초 |           5.36초 |        4.83초 |
| 비용       |        $0* |             $0* |    $0.0036** |

* 로컬 모델 비용은 전력비 제외
** 5개 질문 실행에 사용된 API 비용 기준

### Cloud 비교에서 확인한 점

이번 소규모 비교에서는 GPT-5.6 Luna가 **정확성, 핵심정보 누락, 지시·형식 준수 항목에서 로컬 모델보다 높은 점수**를 기록했습니다.

반면 로컬 모델은 기사 원문을 외부 서버로 전송하지 않고 **로컬 환경에서 독립적으로 실행할 수 있다는 차이**가 있습니다.

따라서 Cloud와 Local은 단순한 품질 비교뿐 아니라 **데이터 처리 방식, 실행 환경, 비용 및 운영 조건**을 함께 고려할 필요가 있습니다.

## 7. 최종 모델 선정

### 최종 선정 모델

**Qwen2.5-7B-Instruct (`qwen2.5:7b`)**

이번 프로젝트의 최종 목표는 **기사 원문이 외부로 전송되지 않고 로컬 환경에서 독립적으로 동작하는 뉴스 QA 시스템**을 구축하는 것이었습니다.

Cloud 모델은 이번 비교에서 높은 품질 점수를 기록했지만, 프로젝트의 핵심 요구사항인 로컬 실행 조건을 기준으로 최종 후보를 Qwen과 EXAONE으로 한정했습니다.

두 로컬 모델을 비교한 결과 다음 요소를 최종 선정의 주요 근거로 사용했습니다.

### 선정 근거

**1. 반복 실행의 일관성**

* Qwen2.5-7B: 100%
* EXAONE 3.5-7.8B: 70%

동일한 질문에 대해 반복 실행했을 때 Qwen의 결과가 더 일관적으로 나타났습니다.

**2. 라이선스 조건**

Qwen2.5-7B는 Apache 2.0 라이선스를 사용하여 프로젝트 이후의 활용 범위 측면에서도 비교적 명확한 조건을 가지고 있습니다.

**3. 품질 차이가 크지 않음**

전체 평가에서는 EXAONE이 일부 항목에서 더 높은 점수를 기록했지만, Qwen도 비슷한 수준의 품질을 보였습니다.

따라서 이번 프로젝트에서는 단순 품질 점수만으로 결정하지 않고 **재현성, 라이선스, 로컬 실행 조건**을 함께 고려하여 Qwen2.5-7B를 선정했습니다.

> Cloud 모델은 향후 데이터 외부 전송이 허용되고 품질을 우선하는 환경에서 비교 대상으로 활용할 수 있습니다.

## 8. 한계점

이번 실험은 모델 선정 단계의 소규모 PoC이므로 다음과 같은 한계가 있습니다.

* 평가셋이 **10문항**으로 구성되어 있어 통계적 유의성을 확보하기 어려움
* Cloud 비교는 **5문항**만 사용하여 로컬 실험보다 평가 범위가 좁음
* 로컬 모델은 2회 반복, Cloud 모델은 1회 실행으로 **반복 횟수가 동일하지 않음**
* 8GB VRAM GPU 1대에서 측정했기 때문에 다른 하드웨어 환경에서는 실행 성능이 달라질 수 있음
* Q7·Q8은 원래 설계한 실제 기사를 확보하지 못해 **가상 기사로 대체**
* `temperature=0`에서도 일부 모델의 반복 실행 결과가 달라지는 현상이 확인되었으나, 해당 원인을 별도로 분석하지는 않음
* 평가 질문 및 채점 기준이 프로젝트 목적에 맞게 직접 설계되었기 때문에 다른 평가셋에서는 결과가 달라질 수 있음
